# Bảng Ánh Xạ Triển Khai Toàn Bộ 68 API Kênh Android (wedding-app)

> **Dự án:** `wedding-app` (Kênh Android / React Native / Expo)  
> **Căn cứ nghiệp vụ:** Phụ lục FPT606 BE–FE Handoff, `01-mobile-srs.md`, `02-mobile-be-fe-handoff.md`, `03-description-api-review.md`, `08-android-68-api-review-fixes.md`  
> **Phạm vi:** Danh mục chuẩn 68 API kênh Android (A68-01 đến A68-68) đã được xác thực chính xác theo OpenAPI contract và mã nguồn thực tế.  
> **Trạng thái:** 68/68 API đã có mã xử lý trong gateway và giao diện UI; phân loại trung thực giữa tính năng hoạt động hoàn chỉnh và tính năng bị chặn bởi kiến trúc backend hoặc thiếu cấu hình native.

---

## 1. Tổng Quan Kiến Trúc Triển Khai

Toàn bộ 68 API được chia theo domain vào 6 gateway chuyên trách và các màn hình/subflow tương ứng trong `wedding-app`:

1. **Identity & Access (`experience-api.ts`)**: 14 APIs (A68-19..26, 54, 56..60) — Màn hình Đăng nhập email/mật khẩu (`login.tsx`), Đổi mật khẩu/Quên mật khẩu bằng OTP email, Hồ sơ cá nhân (`v0-account-tab.tsx`), Quản lý phiên thiết bị (`sessions`), Kiểm tra liveness và readiness độc lập (`/health/live`, `/health/ready`).
2. **Booking Lifecycle & Planning (`planning-api.ts`)**: 10 APIs (A68-01..06, 55, 61..63) — Màn hình Lịch trình tiệc cưới (`TimelineSubflow`), Quản lý đề xuất proposal, Yêu cầu điều chỉnh/hủy tiệc, Điểm danh check-in (`V0GuestsSubflow`), Tổng quan tiệc cưới (`OverviewTab`).
3. **Payments & Billing (`billing-api.ts`)**: 19 APIs (A68-07..18, 47..53) — Màn hình Hợp đồng thương mại (`V0ContractsSubflow`), Phụ lục hợp đồng (`V0AppendicesSubflow`), Hóa đơn quyết toán (`final-invoices`), Chi phí phát sinh, Thanh toán số dư và đặt cọc (`billing.tsx`).
4. **Invitation Studio (`app-invitation-api.ts`)**: 11 APIs (A68-27..37) — Màn hình Thiệp cưới (`v0-invite-tab.tsx`), Quản lý đơn đặt in thiệp giấy (`print`), Xem trước thiết kế, Duyệt/hủy mẫu in, Tải tệp in thiệp A5 (`v0-subflows.tsx`).
5. **Notifications (`notification-api.ts`)**: 9 APIs (A68-38..46) — Màn hình Hộp thư thông báo (`v0-notifications-subflow.tsx`), Phân trang `nextCursor`, Đếm tin chưa đọc, Đánh dấu đọc từng tin / tất cả, Cài đặt kênh nhận tin, Quản lý thiết bị Android.
6. **Public Catalog (`catalog-api.ts`)**: 5 APIs (A68-64..68) — Màn hình Khám phá danh mục nhà hàng (`v0-catalog-subflow.tsx`): Thông tin nhà hàng, Danh sách sảnh & chi tiết sảnh, Gói thực đơn, Danh mục món ăn.

## 3. Các API Hỗ Trợ Kênh Android (Bên Ngoài Danh Mục 68)

Để đảm bảo các luồng trải nghiệm trên mobile không bị đứt gãy, ứng dụng duy trì và bảo toàn các API hỗ trợ đã có:

1. **Media Upload (`POST /media/images`)**: Tải ảnh thiệp cưới và chứng từ trực tiếp lên backend thông qua `uploadMediaImage` (`media-api.ts`).
2. **Public Invitation Viewer (`GET /i/{slug}`)**: Mở giao diện xem trước thiệp cưới công khai trong trình duyệt hệ thống thông qua `openPublicInvitationInAppBrowser` (`media-api.ts`).
3. **Quick Edit Invitation Text (`PUT /invitations/{invitationId}/design`)**: Lưu nhanh các nội dung văn bản (tên cô dâu chú rể, ngày cưới, lời mời) trực tiếp từ Tab Thiệp cưới (`v0-invite-tab.tsx`).

## 4. Báo Cáo Phân Loại Hiện Trạng Nghiệp Vụ

- **Tổng số API thuộc phạm vi:** 68/68 API (A68-01 đến A68-68).
- **Mức độ hoàn thiện mã nguồn (Code + UI Handlers):** 68/68 API (100%) đã có đầy đủ hàm gateway, DTO tương ứng, điểm kích hoạt UI (trigger), xử lý phản hồi và giao diện hiển thị.
- **Tình trạng xác thực Runtime/Native:** *Chưa kiểm chứng trên thiết bị vật lý (Native/Runtime Unverified)* do phạm vi kiểm tra được giao chỉ bao gồm hai cổng tĩnh `npm run typecheck` và `npm run lint`; người dùng sẽ tiến hành kiểm thử tay trực tiếp.
- **Phân loại hiện trạng vận hành:**
  - **66 API:** Đã sẵn sàng luồng xử lý mã nguồn và giao diện người dùng (Code + UI Handlers implemented), bao gồm cả các luồng tiệc cưới trước cọc (`DRAFT`, `AWAITING_DEPOSIT`) đã được mở đường vào `V0CompanionShell` (A68-01 proposal, A68-08 hợp đồng, catalog...).
  - **02 API ghi nhận Blocker hạ tầng / kiến trúc hệ thống:**
    1. **A68-44 (`POST /notifications/android-installations`):** Luồng đăng ký thiết bị với ID ổn định (`SecureStore`, không dùng fallback giả) đã hoàn tất. Tuy nhiên, việc nhận thông báo đẩy FCM thực tế (push delivery) bị chặn do: tệp `google-services.json` chưa liên kết vào `app.config.ts`, `package.json` chưa cài SDK push native (`expo-notifications`), và worker gửi push phía backend đang tắt. Giao diện hiển thị Thẻ chẩn đoán 4 phần trung thực.
    2. **A68-53 (`POST /bookings/{bookingId}/payments/deposit`):** Hàm gọi API và nút kích hoạt đã được triển khai đầy đủ trên màn hình thanh toán. Tuy nhiên, Backend chặn tài khoản Cặp đôi trước cọc trên Android theo SRS BR-05 và Backend Scope 2026-10-10 (`RESTRICTED` Couple workspace chỉ mở trên Web). Giao diện hiển thị cảnh báo `[BLOCKED_BY_BACKEND]` và cung cấp luồng chuyển tiếp sang Web Portal thông qua biến môi trường `EXPO_PUBLIC_WEB_PORTAL_URL` (không đoán URL).
